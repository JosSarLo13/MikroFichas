================================================================================
1. DIRECTRIZ FUNDAMENTAL: CERO SIMULACIONES
================================================================================
MikroManager no es un prototipo visual ni una interfaz ficticia. Toda interaccion
con los routers MikroTik se realiza a traves de su protocolo binario real de sockets
(puerto 8728 en texto plano para redes locales y puerto 8729 con cifrado TLS/SSL).

Reglas de Oro del Sistema:
  1. No inventar APIs ni comandos de RouterOS. Cada funcion mapea a un comando real.
  2. Aislamiento de fallos: La caida, lentitud o corte de un router remoto nunca
     bloquea ni congela el servidor ni perjudica las ventas de otros nodos.
  3. Toda credencial de RouterOS se cifra en reposo con AES-256-GCM y nunca se
     envia al frontend en texto plano.
  4. Si una funcion de RouterOS requiere soporte no nativo (ej. caducidad por reloj
     de pared en lugar de uptime acumulado), se implementa mediante mecanismos
     oficiales documentados (scripts de login y monitoreo de sincronizacion).

================================================================================
2. STACK TECNOLOGICO Y JUSTIFICACIONES
================================================================================

  A. BACKEND API: Node.js 22 LTS + Fastify v5 + TypeScript 5.x
     - Manejo de I/O asincrono no bloqueante de alta velocidad para sockets TCP.
     - Serializacion JSON y validacion de esquemas Zod ultrarrapida.
     - Soporte nativo para WebSockets (telemetria y eventos en tiempo real).
     - Consumo de memoria RAM significativamente menor que frameworks pesados.

  B. BASE DE DATOS Y ORM: PostgreSQL 16 + Prisma ORM
     - Soporte transaccional ACID estricto para compras, ventas y arqueo de caja.
     - Opcion de alternar a SQLite para despliegues embebidos en mini-PCs locales.
     - Migraciones declarativas y tipado fuertemente tipado de extremo a extremo.

  C. DRIVER MIKROTIK: Driver de Socket Nativo Propio (net / tls)
     - Implementacion directa del protocolo de palabras y oraciones (sentences).
     - Decodificador de longitud de bytes (1 a 4 bytes, bitmasks 0x80 a 0xE0).
     - Multiplexacion asincrona concurrente mediante el atributo '.tag'.
     - Connection Pooling y patron Circuit Breaker por router.

  D. FRONTEND: React 19 + Vite 6 + Tailwind CSS v4 + Radix UI
     - Arquitectura modular basada en caracteristicas (features).
     - Interfaz moderna tipo SaaS (estilo Linear/Cloudflare), limpia y profesional.
     - Dark Mode y Light Mode nativo con transiciones sutiles.
     - Estado global con Zustand y cache de consultas con TanStack Query v5.

  E. MOTOR DE IMPRESION Y GENERACION QR:
     - Driver ESC/POS binario para impresion termica directa via Web Serial/USB.
     - Generador de codigos QR compactos y limpios (solo datos indispensables).
     - Generador de planillas A4/A5 con cuadricula de corte punteada para guillotina.

================================================================================
3. ARQUITECTURA HEXAGONAL DEL SISTEMA
================================================================================

El software se estructura en cuatro capas concentricas desacopladas:

  [1] CAPA DE DOMINIO (Domain):
      Entidades puras de negocio (Router, Ticket, Plan, Sale, User, Session).
      No tiene dependencias de bases de datos, frameworks ni librerias externas.
      Define los puertos (interfaces) para repositorios y drivers de red.

  [2] CAPA DE APLICACION (Application - Casos de Uso):
      Orquesta la logica del negocio:
      - GenerateTicketBatchUseCase: generacion masiva con algoritmo anti-colision.
      - ProcessSaleUseCase: registro de venta, comprobante y cambio de estado.
      - DisconnectUserUseCase: desconexion forzada de capa 2/3 en RouterOS.
      - SyncRouterTelemetryUseCase: lectura de CPU, RAM, uptime y trafico.
      - TestRouterConnectionUseCase: validacion de socket y autenticacion.

  [3] CAPA DE INFRAESTRUCTURA (Infrastructure):
      Implementa los adaptadores que conectan con el mundo exterior:
      - MikroTikApiDriver: Socket Pool TCP/TLS, SentenceParser, Circuit Breaker.
      - PrismaRepositories: Persistencia en PostgreSQL/SQLite.
      - CryptoService: Cifrado y descifrado AES-256-GCM.
      - EscPosPrinterService: Emision de bytes directos a impresoras termicas.

  [4] CAPA DE PRESENTACION (Presentation):
      - Controladores REST en Fastify (/api/v1/auth, /api/v1/routers, etc.).
      - WebSockets Gateway para streaming de metricas en vivo (/ws/telemetry).
      - Middlewares de autorizacion RBAC y rate limiting.
      - SPA en React 19 con interfaz responsive.

6. PROTOCOLO DE COMUNICACION Y MATRIZ DE COMANDOS ROUTEROS API
================================================================================

Mecanica del Protocolo:
  - Protocolo binario estructurado en oraciones (sentences) y palabras (words).
  - La longitud de cada palabra se codifica en 1 a 4 bytes prefijados:
      * Longitud < 128 (0x80): 1 byte.
      * Longitud < 16,384 (0x4000): 2 bytes (bit 0x80 encendido).
      * Longitud < 2,097,152 (0x200000): 3 bytes (bit 0xC0 encendido).
      * Longitud < 268,435,456 (0x10000000): 4 bytes (bit 0xE0 encendido).
  - Cada oracion termina con un byte 0x00.
  - Para soportar peticiones asincronas paralelas sobre un mismo socket, cada
    comando se envia con un tag unico '= .tag=ID'. RouterOS responde con dicho
    tag, permitiendo resolver la promesa correcta en memoria sin cruce de datos.

Matriz de Comandos Reales:
--------------------------------------------------------------------------------
Operacion MikroManager  | Comando RouterOS         | Parametros y Respuesta
--------------------------------------------------------------------------------
Prueba de Conexion      | /system/identity/print   | Retorna !re con identity.
Telemetria de Hardware  | /system/resource/print   | Retorna uptime, cpu-load, RAM.
Crear Perfil Hotspot    | /ip/hotspot/user/profile | =name= =rate-limit=
                        | /add                     | Captura !trap si duplica.
Inyectar Ticket/PIN     | /ip/hotspot/user/add     | =name= =password= =profile=
                        |                          | =limit-uptime= =server=all
Desactivar Ficha        | /ip/hotspot/user/set     | =.id=*ID =disabled=yes
Eliminar Ficha          | /ip/hotspot/user/remove  | =.id=*ID
Consultar Conectados    | /ip/hotspot/active/print | Retorna lista de sesiones en vivo
Expulsar Usuario (Kick) | /ip/hotspot/active/remove| =.id=*ID_SESION (Corte Capa 2/3)
Monitorear Trafico      | /interface/monitor-      | =interface=ether1 =once=
                        | traffic                  | Retorna rx-bits y tx-bits
--------------------------------------------------------------------------------

7. ESPECIFICACION DE CRIPTOGRAFIA Y SEGURIDAD
================================================================================

  A. Cifrado de Credenciales MikroTik (AES-256-GCM):
     - Las contraseñas de RouterOS jamas se envian al frontend ni se guardan en
       texto plano en la base de datos.
     - Clave Maestra de 256 bits (32 bytes) provista via variable de entorno.
     - Vector de Inicializacion (IV) criptograficamente aleatorio de 12 bytes
       (96 bits) generado para cada actualizacion.
     - Tag de autenticacion de 16 bytes (128 bits) que previene cualquier
       modificacion maliciosa en la base de datos.

  B. Aislamiento de Fallos mediante Circuit Breaker:
     - Cada router cuenta con una maquina de estados de resiliencia:
         [CLOSED] (Operativo) -> 3 fallos consecutivos -> [OPEN] (Aislado)
         [OPEN] -> Espera tiempo de retroceso -> [HALF-OPEN] (Sonda de prueba)
     - Cuando un router esta caido o apagado, las peticiones fallan en 0 ms con
       un mensaje claro al usuario, sin congelar el backend ni las cajas de venta.

  C. Control de Acceso Basado en Roles (RBAC):
     - SUPERADMIN: Control total del sistema, administracion de routers y usuarios.
     - ADMIN: Administracion general, creacion de planes, perfiles y reportes.
     - OPERADOR: Punto de venta (POS), impresion de fichas y consulta de sus ventas.
     - CONSULTA: Solo lectura de metricas, sin permisos de modificacion ni venta.

8. SISTEMA DE GENERACION DE TICKETS E IMPRESION
================================================================================

  A. Generador Masivo con Algoritmo Anti-Colision:
     - Genera PINs alfanumericos o numericos evitando caracteres confusos (0, O, 1, I, l).
     - Verifica la no existencia previa en la base de datos local y en RouterOS.
     - Throttled Ingestion: Inyecta los usuarios a MikroTik en bloques de 20
       con pausas de 50 ms para mantener la CPU del router por debajo del 15%.

  B. Motor de Impresion Termica Directa (ESC/POS):
     - Emision de secuencias binarias para impresoras de 58mm y 80mm via Web Serial API
       (USB virtual COM) o impresion nativa del navegador con media queries de impresion.
     - Comandos estandar: ESC @ (Reset), ESC a 1 (Centrado), GS v 0 (QR/Graficos),
       GS V 66 0 (Corte de papel).

  C. Planillas de Distribucion A4 / A5:
     - Cuadricula optimizada de 24 tickets por hoja A4 y 12 por A5.
     - Lineas de corte punteadas para guillotina con logo, PIN, tiempo y precio.

9. GUIA OFICIAL DE APROVISIONAMIENTO EN MIKROTIK ROUTEROS
================================================================================

Ejecutar en la terminal de RouterOS (New Terminal en Winbox):

  # 1. Crear grupo de permisos estrictos (sin acceso a FTP, Winbox ni politicas criticas)
  /user group add name=mikromanager-group policy=api,read,write,test,!ftp,!reboot,!policy,!password,!winbox,!web

  # 2. Crear usuario especifico para la plataforma
  /user add name=mikromanager group=mikromanager-group password="CambiarPorClaveSegura2026!#" comment="Usuario MikroManager"

  # 3. Habilitar el servicio API y API-SSL
  /ip service set api disabled=no port=8728
  /ip service set api-ssl disabled=no port=8729

  # 4. Proteger la API en el Firewall (Permitir unicamente la IP del servidor)
  /ip firewall filter add chain=input protocol=tcp dst-port=8728,8729 src-address=IP_DEL_SERVIDOR action=accept comment="MikroManager API"
  /ip firewall filter add chain=input protocol=tcp dst-port=8728,8729 action=drop comment="Bloquear resto de accesos API"
